# EMMAC_Block_v2 accuracy testbench

Purpose: verify that the inverting current-mode multiplier cell resolves the
16 signed input levels (-8..7 uA) for multiplicities k=1..8 under the
half-LSB criterion `|Iout - k*Iin| < 0.5*k*1uA`.

## Files

- `EMMAC_Accuracy.sch` (in `src/analog_mac/`) - xschem testbench, I0 is a DC
  source, V2 sweeps the output bias.
- `EMMAC_Accuracy.spice` (in `simulations/`) - netlist generated by xschem.
- `run_accuracy.py` - driver:
  - `--mode nominal`  full grid k=1..8 x Iin=-8..7uA x Vout=0.2..1.6V,
    writes one ASCII raw per point plus `summary.csv`.
  - `--mode corners`  same grid for mos_tt/ss/ff/sf/fs
    (optional `--temps`), results in `corner_<tag>/`.
  - `--mode mc --runs N`  mismatch Monte Carlo
    (`mos_tt_mismatch`, `reset`/`run` loop, chunked to avoid ngspice
    slowdown over long reset loops), reduced Vout grid
    (0.4/0.9/1.4 V), writes `mc_results.csv`.
    `--mc-set reduced` uses k in {1,2,4,8} and Iin in {-4,-1,0,1,4}
    (~6x faster; used for the 200-run result).
  - `--analyze-only` re-analyze an existing run dir.
  - `--sign -1` when the measured transfer is Iout ~ +k*Iin (current measured
    polarity of this cell); use `--sign 1` for the ideal inverting convention
    Iout = -k*Iin.
- `make_report.py` - rebuilds `REPORT.md` from the run directories.
- `probe_op.py` - single op point (k=8, Iin=+7uA) with output-branch currents.

## Run

```
cd simulations/accuracy
python3 run_accuracy.py --mode nominal --sign -1
python3 run_accuracy.py --mode corners --sign -1
python3 run_accuracy.py --mode mc --runs 200 --sign -1
python3 make_report.py
```

### v3 (gate-steered output)

```
python3 run_accuracy.py --mode nominal --sign -1 \
    --prefix _v3 --netlist EMMAC_Accuracy_v3.spice
python3 run_accuracy.py --mode corners --sign -1 \
    --prefix _v3 --netlist EMMAC_Accuracy_v3.spice
python3 run_accuracy.py --mode mc --runs 200 --mc-set reduced --sign -1 \
    --prefix _v3 --netlist EMMAC_Accuracy_v3.spice
python3 make_report.py --prefix _v3     # -> REPORT_v3.md
```

`--mult-device` overrides the auto-detected `@n.<inst>.<dev>.n<model>` path
of the `m={wmul}` device.

## Notes

- The cell's measured transfer is non-inverting in this testbench
  (Iout ~ +k*Iin). The ideal sign only changes the reported error if the MAC
  input-current convention is opposite.
- `wmul=0` is not tested: with m=0 the ngspice PSP multiplier is invalid and
  the MAC should disconnect the cell instead.
